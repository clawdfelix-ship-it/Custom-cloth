# 分類中文化設計稿

## 目標

- 將 storefront 可見的 M-ZAKKA 分類名稱由日文優先改為繁體中文優先。
- 先令前台即時見效，再逐步回填 `categories.name_zh_hk`，避免資料層長期停留在日文。
- 保持品牌名、系列名、型號原文，避免錯譯或出現不自然中文。

## 已確認規則

- 採用雙軌方案：
  - 前台先做字典翻譯覆蓋，立即生效。
  - 同步提供 DB 回填腳本，逐步更新 `categories.name_zh_hk`。
- 翻譯原則：
  - 通用分類詞翻中文，例如 `メーカー別`、`タイプ・サイズ別`、`特徴・内部構造別`。
  - 品牌、系列、型號、英數商品線名稱保留原文。
  - 翻譯表未命中的詞維持原文，不作機器直譯。

## 現況

- storefront 分類樹現時主要顯示 `COALESCE(name_zh_hk, name)`。
- 由於大量 M-ZAKKA 分類在匯入時以原文暫代 `name_zh_hk`，所以前台仍見到日文。
- 前台分類入口已分散在多個地方：
  - 桌面左欄分類樹
  - 手機版分類 drawer
  - `products` 頁當前分類標題
  - header 分類選單

## 設計

### 1. 新增分類翻譯字典

- 建立一個可被前台 render 與 scripts 共用的分類翻譯模組。
- 模組輸入單一分類名稱，輸出：
  - `translatedName`：翻譯後名稱或原文
  - `didTranslate`：是否命中字典
- 首批翻譯只涵蓋高頻通用詞，例如：
  - `メーカー別` -> `按品牌`
  - `タイプ・サイズ別` -> `類型・尺寸`
  - `特徴・内部構造別` -> `特徵・內部構造`
  - `素材別` -> `按素材`
  - `パッケージタイプ別` -> `包裝類型`
  - `二次元イラスト` -> `二次元插畫`

### 2. 前台即時顯示覆蓋

- 在 storefront category tree 建立時就套用翻譯，而不是在單一 template 臨時字串替換。
- 覆蓋範圍：
  - `res.locals.categories`
  - `res.locals.categoriesTree`
  - `products` 頁選中分類名稱
  - header 分類 `select`
- 原始 `slug`、`id`、`parentId`、count 不變，只改顯示名。
- 若 `name_zh_hk` 本身已是繁中，優先沿用，不再覆蓋。

### 3. DB 回填策略

- 新增一支腳本，掃描 `categories` 表，針對「可安全翻譯」的通用分類詞更新 `name_zh_hk`。
- 更新條件：
  - 僅當現有 `name_zh_hk` 為空、等於原文、或屬於已知原文暫代值時才更新。
  - 品牌名、系列名、未知詞不更新。
- 腳本需輸出：
  - 更新數量
  - 跳過數量
  - 未命中字典的分類例子，方便後續人工補表

### 4. 一致性要求

- 同一分類名稱在桌面左欄、手機 drawer、header select、頁面標題顯示一致。
- 同一套翻譯字典同時被 storefront 與 backfill script 使用，避免兩邊各自維護。

## 風險與處理

- 風險：品牌名誤被翻譯。
  - 處理：只對命中字典的通用詞做映射，不做自動機器翻譯。
- 風險：部分分類 path 混合品牌與通用詞，顯示不一致。
  - 處理：以節點級別翻譯，每個 category node 只翻自己名稱，不拆 slug、不改 path 結構。
- 風險：DB 回填覆蓋已有人工中文。
  - 處理：腳本只更新「空值 / 原文暫代」記錄，不強制覆蓋已有中文。

## 驗收標準

- `/products` 左欄分類樹主要通用分類詞顯示繁中。
- 手機分類 drawer 顯示與桌面左欄一致。
- `products` 頁標題與 header 分類選單跟隨同一翻譯規則。
- 回填腳本可重跑，且不會覆蓋既有人工中文分類。
- 未命中字典的分類仍可正常顯示原文，不影響分類連結與查詢。

## 非目標

- 不做商品名稱、商品描述全面翻譯。
- 不做品牌中文命名標準化。
- 不在今次處理分類 SEO slug 或 URL 結構變更。
