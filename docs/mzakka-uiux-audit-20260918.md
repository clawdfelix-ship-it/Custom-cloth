# M-ZAKKA（mzakka.com）前端 UI/UX/排版完整分析

> 以 agency-agents 之 **UX 研究員（啟發式評估）+ UI 設計師（視覺/排版系統）** 角度
> 實測日期：2026-09-18｜工具：真機瀏覽器 DOM/CSS 量度 + curl（桌面 1440×900、手機 375×812、iPhone UA）
> 性質：日本成人用品電商（舊名 MAN-ZOKU／マンゾクショッピング），nginx + jQuery 1.12.4 + bxSlider

---

## 0. 一句總結

**典型 2000 年代後期「高密度日本入口網站」版型，桌面與手機是兩套獨立老舊碼：桌面版寫死 1065px、零 media query、完全唔響應式；手機版勉強可用但 tap target 95% 過細、table 排版。** 功能與商品密度高（對熟客/回購有利），但喺現代可用性、手機體驗、無障礙、效能、SEO、可維護六方面都明顯過時。

---

## 1. 架構真相：唔係響應式，係「兩個網站」

| | 桌面版 `/pc/` | 手機版 `/sp/` |
|---|---|---|
| 分流方式 | 預設 | 伺服器按 `User-Agent` 302（`Vary: User-Agent`）|
| viewport meta | **`width=1065`（寫死）** | `width=device-width,initial-scale=1.0,minimum-scale=1.0` |
| media query 數量 | **0** | **0**（固定手機版，唔係自適應）|
| 排版技術 | table(13) + `float:left` + 固定 1065px 容器 | table(20)，固定手機寬 |
| 基礎字級 | **12px** Meiryo | 16px Hiragino（擋 iOS 自動縮放，呢點啱）|
| HTML 大小（首頁）| 280 KB | 23.7 KB |
| `<img>` 數（首頁）| 292 | 117 |
| `loading=lazy` | **0** | **0** |
| `<table>` / `<div>` / `<a>` | 13 / 423 / 1442 | 20 / 217 / 344 |
| `<h1>` | 有（1 個）| **完全冇 h1** |
| 語義 landmark | 冇 `<nav>/<header>` | 冇 |

**實測驗證**：桌面瀏覽器縮到 375px，首場依然被當 1065px → `scrollWidth 1065 > clientWidth 375`，**強制横向 scroll**；要入 `/sp/` 只能靠手機 UA（桌面 UA 開 sp 深頁被彈返 pc）。

### 點解係問題
- **雙碼維護**：任何改動要改兩套模板、兩套 URL、兩套測試，長期必然不同步（例如手機版漏 h1）。
- **UA 偵測脆弱**：iPad、桌面拉窄視窗、新裝置 UA 易判錯；`/sp/` 嘅 canonical 指返 `/pc/`（呢點 SEO 處理正確）。
- **中間尺寸冇人理**：細手提電腦 1280、平板直點 768 一律食 1065px 或被分流，體境斷層。

## 2. 電腦版（/pc/）逐項

### 2.1 整體佈局
- 固定 **1065px 居中**（1440 視窗下左起 x=188，兩側大片留白），內容主欄 `950/930px float:left` + 左/右側欄。
- 全頁**極長 scroll**：排行榜、實演販賣、新商品、PICK UP、目玉、關鍵字搜尋、登入、分類、出荷予定、最近睇過、店長推介……一頁塞十幾個區塊。
- 1442 個連結、344 張圖 —— 資訊密度極高，屬「楽天/Yahoo!JAPAN 式」密集 portal 風格。

### 2.2 商品列表（核心畫面）
- 商品卡係 **`float:left` 的 `<li>`，一列 4 欄，每卡只有 152px 闊、卻高 300–350px**。
  - 卡片**又瘦又長、高度參差**（304/332/348/350），float 錯位時容易留空洞、不對齊。
  - 152px 內要放圖 + 長日文商品名（被擠成極多行）+ 定價 + 紅字特價 + 按鈕，視覺擁擠。
- 分頁用「2 3 4 … 10 + 次へ」數字列，且 DOM 中**出現兩組重複分頁**。
- 篩選係 **6 個以上下拉選單**（category / inameonly / orand / cat3 / cat4 / cat5），命名抽象、各自獨立，顧客好難理解邊個打邊個；冇常見嘅 facet checkbox（品牌/價格區間/規格）。

### 2.3 視覺層次
- 深酒紅（maroon/burgundy）header + 大量促銷 banner；價錢用「灰色刪除線 通常価格 12px」對「**純紅 #ff0000 特價 16px**」。
- 紅色純 #f00 + 12px 主字級，對比與現代節奏偏弱；全頁靠大細 banner 同紅字製造層次，缺乏統一 spacing/字級 scale（量度所見字級零碎 12/13/14/16/22）。

## 3. 手機版（/sp/）逐項

### 3.1 做得對的地方
- viewport 正確、375px **冇横向 scroll**；基底 16px 防 iOS input zoom。
- 首頁比桌面輕（23.7KB）、區塊收斂成 7 個 h2（新商品/売れ筋/目玉/PICK UP/新着情報/実演/分類検索）。
- 固定底部/頂部入口：fixed 漢堡選單（z990：ログイン/カート/検索/新着/新商品/カテゴリ/セール）、右下沉回頂掣 52×89。

### 3.2 致命傷：觸控目標過細
- 實測 **334 個可見 tap target，316 個（95%）細過 Apple HIG 44pt／WCAG 建議**。
- 樣本：`45×34`、`30×35`、`39×35`、`93×30`、大量 `…×16px` 文字連結。
- 手指易誤觸、誤入商品/誤跳轉，係手機電商轉化嘅直接殺手。

### 3.3 商品列表
- **2 欄 grid、商品圖寫死 `width="150"`**（一頁 HTML 出現 200 次 width=150）。
- 375px 放 2×150 + 間距幾乎貼邊；仍用 table/固定像素，喺 320px 舊機或字級放大時會逼爆。
- 商品名同價錢區塊 tap 區同上偏小。

### 3.4 結構/語義
- **冇 `<h1>`**（只有 h2），SEO 主題權威同屏幕閱讀器大綱都受損。
- table 排版、缺 landmark、4 張圖缺 alt。

## 4. 跨裝置共性問題（啟發式評估）

1. **年齡確認閘**：`#fullscreen2` fixed z-999 全屏覆蓋（桌面+手機都有）。問題係「進入」鈕嘅 markup 似乎被注入每一個 form（每個 form 頂都見到 `fullscreen2yes_btn`），HTML 結構髒、易引致表單提交異常；亦冇做焦點囚禁/Esc/aria-modal（對比我哋 Ohya2.0 啱啱修嘅 P8）。
2. **效能**：兩版都**零 lazy-load**，桌面首頁 292 圖、手機 117 圖即載；DOM 節點龐大、15/11 個 script、多支外聯 tracking（dataLayer、afblpcv…）；jQuery 1.12.4（2016，有多個已知 XSS CVE）。
3. **無障礙（遠低 WCAG AA）**：12px 主字、95% tap 過細、缺 alt、缺 landmark/main/nav、表單 label 不足、紅價 #f00 在白底對比雖合格但淺灰小字（#999 類）對比不足、冇可見 focus ring 管理。
4. **資訊架構貨櫃式**：咩都擺首頁，靠「排行榜/実演/店長推介」等日式促銷模組堆疊；新客認知負荷高，熟客就覺得方便——屬雙面刃。
5. **篩選/搜尋心智模型過時**：多個神秘 dropdown，缺乏麵包式 facet、 sorting 可視化、結果計數。
6. **可信度元素其實充足**（呢點值得保留/學習）：売れ筋ランキング、出荷予定表（出貨日程）、最近睇過商品、通常價/特價對比、实演販売——電商轉化同回購嘅常用招都有。

## 5. 優先級建議（若要仿傚／改良自己舖頭）

### P0（立即，影響手機轉化）
- Tap target 全面 ≥44×44px、相鄰可點元素留 ≥8px 間距。
- 商品列表由 table/float 改 **CSS Grid/Flexbox 響應式**：手機 2 欄、≥640 3 欄、≥1024 4 欄；卡片統一高度、圖用 `aspect-ratio`。
- 商品圖全量 `loading="lazy"` + 明確 `width/height` 防 CLS。

### P1（架構/可維護）
- **一套響應式碼取代 /pc + /sp 雙站**（或至少共用 component/資料層），廢除脆弱 UA 偵測；保留 `<link rel=canonical>` / alternate 處理過渡期 SEO。
- 移除寫死 `width=1065`，改用 `device-width` + media query（360/768/1024/1280 斷點）。
- 升級或移除 jQuery 1.12.4；表單內殘留嘅年齡閘按鈕要清走。

### P2（無障礙/SEO）
- 補 `<h1>`（每頁唯一）、`header/nav/main/footer` landmark、alt、表單 label、可見 `:focus-visible`、年齡 modal 做 Esc＋焦點囚禁＋`aria-modal`。
- 基底字級由 12px 提升至至少 14–16px；淺灰小字對比過 AA（4.5:1）。

### P3（資訊架構/體驗）
- 篩選改 facet（分類/品牌/價格/排序）+ 結果數；分頁統一一組、加「上一頁/下一頁」aria-label。
- 首頁用清晰 section 標題與留白節奏，保留排行榜/出荷予定/最近睇過等有效模組，但以卡片網格取代無盡長陣。

## 6. 對我哋 Ohya2.0 嘅啟示（抄好嘅、避壞嘅）
- **保留**：人氣排行榜（真銷量聚合）、出貨/日程資訊、最近瀏覽、原價/特價對比、明確缺貨態——呢啲日式成熟電商轉化元素我哋已執。
- **唔好抄**：寫死像素寬、雙站 UA 分流、table/float、細字、細 tap、零 lazy、jQuery 古董、首頁無限長、神秘多 dropdown。
- 我哋 P8（focus/modal a11y）、P10（375px 購物車響應式列）正好補正呢類站嘅典型缺陷，方向正確。
